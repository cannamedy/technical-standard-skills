# Distractor Design

Every distractor should represent a plausible reasoning failure. Random nonsense, unrelated trivia,
and obviously absurd options do not diagnose understanding.

## Distractor taxonomy

Use one or more of these labels when applicable:

1. correct principle, wrong layer;
2. correct mechanism, wrong scope;
3. correct fact, wrong timing;
4. correct authority, wrong object;
5. correct static rule, wrong dynamic interpretation;
6. correct local rule, wrong global generalization;
7. correct reference implementation mistaken as normative standard;
8. correct abstraction, wrong responsibility owner;
9. correct state mistaken as intent;
10. correct intent mistaken as fact;
11. declared capability mistaken as currently available capability;
12. observation mistaken as authoritative state;
13. safety validation mistaken as total safety guarantee;
14. transport behavior mistaken as semantic requirement;
15. implementation convenience mistaken as architecture law;
16. correct dependency hidden at the wrong layer;
17. correct recovery technique unsafe for physical side effects;
18. correct value missing physical context;
19. correct concept over-generalized beyond its contract;
20. correct conclusion under one condition applied after the condition changed.

## Construction test

For each wrong option, record the misconception and ask:

- Would a partially informed learner plausibly choose it?
- Does it fail for a specific reason connected to the source?
- Is that reason distinct from the other distractors?
- Could flawed reasoning reach the correct option instead?

Keep options at comparable semantic granularity and specificity. A distractor can be partially true,
but the stem must contain a condition that makes the best answer unique.
