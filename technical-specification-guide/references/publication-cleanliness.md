# Publication Cleanliness

A technical publication should primarily contain information about the technical subject.

## Normally remove

- editing-round commentary;
- "golden master" references;
- Skill names;
- model names;
- internal acceptance verdicts;
- Git workflow;
- "this section was added to...";
- "the following was preserved...";
- repeated explanations of document type.

## May remain when useful

- document title;
- release status;
- intended scope;
- intended audience when non-obvious and useful;
- normative/informative status;
- relationship to other official specification documents.

## Reader-value test

For each sentence ask:

"If the reader did not know how this document was produced, would this sentence still help them understand or use the technical system?"

If no, remove or move it to internal project documentation.
