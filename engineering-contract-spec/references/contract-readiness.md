# Contract Readiness Gate

Before creating implementation tasks, review the current Contract for:

- stable canonical terminology;
- identified architecture source;
- stable Requirement IDs or Section Anchors;
- defined major boundaries;
- sufficient state machines for the claimed scope;
- expected failures and rejection behavior;
- ownership and authority;
- safety responsibility where applicable;
- conformance landing points;
- resolved load-bearing open issues;
- separation of deferred and current mandatory scope.

Report one of:

- `CONTRACT READY FOR IMPLEMENTATION PLANNING`
- `CONTRACT NOT READY FOR IMPLEMENTATION PLANNING`

When not ready, list the affected requirements and issues. Continue only with unaffected scope.
